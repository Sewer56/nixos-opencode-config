### Documentation context

Apply doc rules by audience, reader task and document type.
Concision applies to source docs/comments, guides, references and instructions.

Match comparable concise docs' structure and depth, not the longest section.
Depart only when requirements justify it.

Apply source/API duties only to source/API docs.
Preserve explicit requirements, contracts and complete changed-API errors.

Keep consequential safety/compatibility caveats.
Guides support reader actions; maintainer docs explain needed mechanisms.

Use the shortest explanation that serves the reader's task.
Delete text unless removal impairs action, decisions or required understanding.

Technical truth or possible usefulness alone does not justify inclusion.
Omit consequences already clear from defaults, option definitions or examples.

State facts once where owned.
Link configuration/contracts instead of repeating them.
Do not create docs to relocate unnecessary detail.

Examples show the relevant choice, not every supported field.
Preserve necessary text and examples; impose no length quotas.
