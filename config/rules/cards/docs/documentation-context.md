### Documentation context

Apply doc rules by audience, reader task and document type.

Match comparable nearby docs' structure and depth.
Depart only when requirements justify it.

Apply source/API duties only to source/API docs.
Preserve explicit requirements, contracts and complete changed-API errors.

Keep consequential safety/compatibility caveats.
Guides support reader actions; maintainer docs explain needed mechanisms.

Technical truth alone does not justify inclusion.
State facts once where owned.

Link configuration/contracts instead of repeating them.
Do not create docs to relocate unnecessary detail.

Keep useful text and examples; impose no length quotas.
